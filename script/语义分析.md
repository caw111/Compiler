# 语义分析

在完成语义分析之后，我们已经画出了 AST 语法树，在这个基础上我们进一步进行对这个语义分析，主要包括两个方面的内容：

1. 建立符号表
2. 错误检测

其实错误检测也是在建立符号表的过程中同步进行的

## 语义分析总体结构

```txt
semantic
├── ErrorController.java
├── ErrorToken.java
├── SemanticAnalyse.java
└── symbolTable
    └── symbol
        ├── FuncSymbol.java
        ├── StackSymbolTable.java

```

这里 `FuncSymbol` 类是 `Symbol` 的子类，`SymbolTable` 是总的符号表，`StackSymbolTable` 负责管理不同层级的符号表，`SymbolType` 是符号类型的枚举类，`SymbolTypeMap` 是通过字符串得到对应符号类型的一个辅助类。语义分析的主逻辑在 `SemanticAnalyse` 中，剩余的两个和 `Error` 相关的类负责记录语义分析中检测的错误。

## 符号表的建立

语义分析的第一步是建立符号表，从上次完成的语法分析得到的最后的AST语法树开始构建符号表，对于一个符号表来说，一方面需要能够在声明一个变量的时候将符号保存到表中，同时在后续调用对应的变量或者函数的时候也能够通过符号表快速找到这个符号。对于实验的源代码来说，由于存在符号的分层机制，所以可以在不同的层次来声明同一个名称的变量，就像下面这种情况：

```C
int a = 1;
{
    int a = 2;
}
```

这样是合理的，在下面这个 block 中使用的 a 应该优先从当前这个作用域开始查找，找不到再从外层作用域一个一个找。那我们建立的符号表也要能够具有这个功能。

### 符号 Symbol 类

先从这个符号表中的符号类开始说明，通过上面对于作用域的说明，我们的每一个符号类都至少有以下这些属性：

1. 符号名 `symbolName`
2. 符号种类 `symbolType`
3. 符号所在作用域 `symbolLevel`

目前就这些就足够了，但是后续还是要增加一些属性。这里的 符号种类 `symbolType` 实际上是自己定义的一个枚举类 `SymbolType` ，这个枚举类定义了符号的所有类型：

```java
public enum SymbolType {
    Int, ConstInt, StaticInt, IntArray, ConstIntArray, StaticIntArray,
    Char, ConstChar, StaticChar, CharArray, ConstCharArray, StaticCharArray,
    VoidFunc, IntFunc, CharFunc,
}
```

当然这样的符号定义远远不能满足我们的需求，尤其是当我们要处理一个函数的符号的时候：

```C
int f(int a, int b, int c) {
    ………………
}
```

当我们想要记录这个函数对应的符号的时候我们会发现上面的三个属性完全不足以记录函数的信息，我们还需要记录这个函数的 

1. 返回类型  

2. 参数列表

这里可以很容易想到可以以之前的 Symbol 作为基类，生成一个子类 `FuncSymbol` ，在原来的基础上增加了上述的两个属性。

```java
public class FuncSymbol extends Symbol {
    List<SymbolType> list;
    private SemanticAnalyse.ExprType returnType;
    public FuncSymbol(String symbolName, SymbolType symbolType, int symbolLevel, int scopeLevel, List<SymbolType> list, SemanticAnalyse.ExprType returnType) {
        super(symbolName, symbolType, symbolLevel, scopeLevel);
        this.list = list;
    }
    public List<SymbolType> getList() { return list; }
}
```

这里的返回类型 `ExprType` 写在 `SemanticAnalyse` 中，这样设计没有什么别的原因，就是觉得类写的太多，就放在这里面没有提出来了…… 写这个类的主要原因在于可以观察这个函数定义的文法：

```SysY
bType
    : 'int'
    | 'char'
    ;
    
funcDef
    : funcType IDENT '(' funcFParams? ')' block
    ;
    
funcType
    : 'void'
    | 'int'
    | 'char'
    ;

funcFParams
    : funcFParam (',' funcFParam)*
    ;

funcFParam
    : bType IDENT ('[' ']')?
    ;
```

从这里可以看到，对于一个函数的声明，函数的返回类型只有三种：`int` ， `char` ，`void` ，而传入的参数类型也只有 `int`，`char`，以及对应的数组类型。所以这边就写了一个 `ExprType` 类：

```java
    public enum ExprType {
        INT,
        CHAR,
        INT_ARRAY,
        CHAR_ARRAY,
        VOID,
        ERROR
    }
```

这个类的作用很大，不仅现在用于记录函数对应的信息，在后续表达式计算的过程中还会大量使用。

### `SymbolTable` 符号表

 完成了对于 `Symbol` 的定义之后，接下来就是对这个符号表类型的设计了。前面提到了，这个 `SymbolTable` 是一个总的符号设计表，实际上的符号设计表是分层进行存储的，对于每一个作用域定义对应的符号表。按照这个思路，其实这个 `SymbolTable` 的设计就很简单：

```java
public class SymbolTable {
    private final HashMap<Integer, StackSymbolTable> symbolTables = new HashMap<>();  // 每个分析器独立的符号表

    public HashMap<Integer, StackSymbolTable> getSymbolTables() {
        return symbolTables;
    }

    public SymbolTable() {
        symbolTables.put(0, new StackSymbolTable());
    }

    public boolean addSymbol(Symbol symbol) {
        // 如果当前层为空，新建一个 symbolTables
        StackSymbolTable stackSymbolTable = symbolTables.computeIfAbsent(
                symbol.getScopeLevel(),
                id -> new StackSymbolTable()
        );
        // 如果返回 true 表示成功插入一个空位置，返回 false 表示重定义
        return stackSymbolTable.getSymbolStack().putIfAbsent(symbol.getSymbolName(), symbol) == null;
    }

    /* 在对应的层中查找符号 */
    public Symbol findInScope(String symbolName, int scopeLevel) {
        StackSymbolTable stackSymbolTable = symbolTables.get(scopeLevel);
        if(stackSymbolTable == null) {
            return null;
        }
        return stackSymbolTable.getSymbolStack().get(symbolName);
    }

    public void printSymbolTable(BufferedWriter fwOut) throws IOException {
        List<Integer> scopeLevels = new ArrayList<>(symbolTables.keySet());
        Collections.sort(scopeLevels);

        for(Integer scopeLevel : scopeLevels) {
            StackSymbolTable stackSymbolTable = symbolTables.get(scopeLevel);
            for(Symbol symbol : stackSymbolTable.getSymbols()) {
                if (!symbol.getIsBuiltin() && !"main".equals(symbol.getSymbolName())) {
                    fwOut.write(scopeLevel + " " + symbol.getSymbolName() + " " + symbol.getSymbolType() + "\n");
                }
            }
        }
    }
}

```

实际上对于这个总表来说只有一个属性，就是这个Map，将作用域的层数和他对应的 `StackSymbolTable` 联系起来。所以实际上具体存储符号的逻辑在 `StackSymbolTable` 中：

```java
/* 栈式符号管理当前这一层所拥有的符号 */
public class StackSymbolTable {
    private Map<String, Symbol> SymbolStack = new LinkedHashMap<>();

    public Map<String, Symbol> getSymbolStack() {
        return SymbolStack;
    }
    public Collection<Symbol> getSymbols() {
        return SymbolStack.values();
    }
    public void setSymbolStack(Map<String, Symbol> symbolStack) {
        SymbolStack = symbolStack;
    }
    public void addSymbol(Symbol symbol) {
        getSymbolStack().put(symbol.getSymbolName(), symbol);
    }
    // 判断这个符号是否在这个表中
    public boolean isHaveSymbol(Symbol symbol) {
        Symbol tmp = getSymbolStack().get(symbol.getSymbolName());
        if(tmp == null) {
            return false;
        }
        return true;
    }
}
```

那这个栈式符号表就更加简单了，只需要一个Map把对应的符号名称和其对应的 Symbol 对应起来就行。这里就是重点说这里对外提供的方法：对于每一层栈式符号表来说，应该能够向这个栈中添加新的符号，因为需要记录这个符号的先后顺序（后续输出需要），这里使用 `LinkedHashMap` ，来记录这个Map。添加和检查是否存在符号的逻辑比较简单。这里为了后续最后输出答案，还写了一个 `printSymbolTable` 方法，可以按照顺序向给定的 `BufferedWriter` 写入符号表的具体内容。

### 语义分析

在完成了上述这些准备工作后，就可以正式开始语义分析。按照前面所说这一部分主要完成的有两件事：建立符号表，检测语义错误。

这里要注意的是，这两个工作必须要同时完成，也就是说检测语义错误应该在符号表建立的过程中一起完成。这很容易理解，比如我现在有程序：

```java
int a = 1;
b = 2;
int b = 3;
```

如果我把符号表都建立好了，那对于这一层中有符号a 和 b，这个时候 b = 2检测不出来错误。我们需要的是在符号表还没有把 b 放进符号表之前就把这个 b 未定义的错误输出了。

ok，知道了这一点具体我们该怎么做呢？实际上语义分析是一个非常巨大的工程，想要全部完成是非常消耗精力并且复杂的。这里我的建议是一点一点的完成。

#### 1. 对符号的解析

第一步我的建议是完成对符号表的建立，其余错误可以先放在一边。这样做的原因有2点：

1. 建立符号表是必须的，同时也是后续错误检测所必须的基础
2. 建立符号表实际上只需要对声明语法进行处理，工程量较小，适合上手

这里我们只处理一个问题：符号重复定义。其余的后面再做：

观察给定语法，实际上声明一个符号的语法只有这几个：

```SysY

    ;

varDecl
    : 'static'? bType varDef (',' varDef)* ';'
    ;
```

```java
    // 将对应的 BType 的位置转换成对应的类型
    private String getBType(AstNode node) {
        Token token = node.isTerminal()
                ? node.getToken()
                : node.getChildren().get(0).getToken();

        return switch (token.getType()) {
            case INTTK -> "Int";
            case CHARTK -> "Char";
            case VOIDTK -> "Void";
            default -> throw new IllegalStateException("不是类型关键字");
        };
    }
```

这里主要要注意的就是虽然语法中出现了 `<BType>` 这个东西，但是在我们生成树的时候实际上是没有这个 `<BType>` 节点的，所以我们应该像上面的代码写的那样直接看当前是不是叶节点，然后对应的token类型来判断，不能找 `<BType>` 节点。

同时这里还要注意这个对 `level 和 scopeID` 的处理。这个地方还是有一些问题的，这里就直接说明本处的设计，这里我也是参考了 ai 的建议，这个level是我本来自己设计的，用来标志这个层次，但是我的设计有很大的问题，在这个地方可以完全不管了。这个 `scopeID` 用来完成对这个符号所在的作用域进行管理，这里使用的也是一种栈式的方式，使用一个栈来保存层次，进入一个新的层次的时候就把当前所在的层次号入栈，并且把新的层次变为 `nextScopeID + 1`， 在完成了当前层次的内容之后，再弹出栈顶的元素，赋值给 `scopeID`。通过这样的方式实现了对符号进行分层的管理。

```java
private int scopeId = 1; // 当前所在作用域
private int nextScopeId = 1;    // 下一个进入的作用域
private Deque<Integer> scopeStack = new ArrayDeque<>();
private void levelUp() {
    // 保存父作用域编号
    scopeStack.push(scopeId);
    // 创建新的作用域编号
    scopeId = ++nextScopeId;
}

private void levelDown() {
    // 恢复父作用域编号
    scopeId = scopeStack.pop();
}
```

这个地方其实关键在于 `scopeID` 更新的时候是根据这个 `nextScopeID + 1` 来进行的，不能使用 `scopeID + 1` 来进行。后者的问题在于，比如现在有一个源代码： 

```C
{ // a
    int a = 1;
    { // b
        int b = 1;
    }
}

{ // c
	int b = 1;    
}
```

如果按照 `scopeID + 1` 来进行更新的话就会出现 b 和 c 两处属于同一个 `scopeID` ，这就会被认为这个 b 重复定义了，但是很显然这样是不正确的。按照 `nextScopeID + 1` 来更新就避免了这个问题。

```java
    private void extractFuncDef(AstNode node) {
        // 这个地方要注意参数的插入顺序：先函数，后函数的参数，最后是block中的内容，顺序不能错误
        String type = null;

        AstNode paramsNode = null;
        AstNode blockNode = null;
        Token token = null;

            if (!child.isTerminal() && child.getName().equals("<FuncType>")) {
                type = getBType(child);
            }
            if (child.isTerminal()
                    && child.getToken().getType() == TokenType.IDENFR) {
                symbolName = child.getToken().getLexeme();
                token = child.getToken();
            }
            if (!child.isTerminal() && child.getName().equals("<FuncFParams>")) {
                paramsNode = child;
            }
            if (!child.isTerminal() && child.getName().equals("<Block>")) {
                blockNode = child;
            }
        }
        // 2. 仅提取形参类型，不插入形参符号
        List<SymbolType> paramTypes = new ArrayList<>();
        if (paramsNode != null) {
            paramTypes = collectParamTypes(paramsNode);
        }
        // 3. 注册函数符号
        SymbolType symbolType = getFuncType(type);
        FuncSymbol funcSymbol = new FuncSymbol(
                symbolName, symbolType, level, scopeId, paramTypes, variableType(getFuncType(type))
        );
        declare(funcSymbol, token);

        // 4. 进入函数作用域
        ExprType previousType = currentExprType;
        currentExprType = variableType(getFuncType(type));
        levelUp();
        scopeId = nextScopeId;
        // 5. 注册形参
        if (paramsNode != null) {
            extractFuncFParams(paramsNode);
        }
        // 6. 遍历函数体子节点
        if (blockNode != null) {
            for (AstNode child : blockNode.getChildren()) {

            }

        if(currentExprType == ExprType.CHAR || currentExprType == ExprType.INT) {
```

### 错误检测

首先观察给定的错误类型列表，除了在词法分析和语法分析中会出现的错误外，剩下的在语义分析中可能出现的错误中，除了错误类型 b（名字重定义）和 f（无返回值的函数有不匹配的return）， g（有返回值的函数没有return） 这几种错误会出现在符号的定义过程，其余错误几乎就都是在使用符号的过程中才会出现。而这些错误大多数都和类型有关。这里的类型其实就是前面定义的这个枚举类 `ExprType` 。在后续的错误检测中，这个类型会非常普遍的被使用。这里的难点在于这里会出现大量的表达式相关的内容。比如源代码中可能会出现这样的内容：

```C
int a = 1;
int b = a + a * a - 1 ;
```

可以看到这个 b 的初值不是一个常量，而是一个表达式，这个时候进行语义分析的时候，为了判断 b 定义的类型和后面的表达式的类型是否一致时，就无法避免的需要对后面这个表达式进行处理。而这种类似的情况非常普遍的出现在各种位置。所以在进行后续的语义错误检测的时候，我们应该首先完成这个对表达式的类型的解析工作。需要实现的效果就是对于这种表达式，一方面能够找到表达式自己在计算的时候类型是否正确对应，另一方面就是这个表达式运行得到的最终类型。

仔细观察文法（或者使用 gpt），可以对表达式进行如下分类

1. `Exp`、`ConstExp`、`Cond`：直接向下传递，在当前文法中，只有一个用于承载表达式的子节点，自己不引入新的运算。

2. `Number`：直接确定类型，可以通过对 `Number` 下面的 token 进行分析得到对应的类型

3. `PrimaryExp`：根据产生式选择子节点，并有多种选择

4. `LVal` ：使用一个符号，包括普通变量和数组

5. `PrimaryExp` : 有多种选择

6. `AddExp` 和 `MulExp` ： 普通计算的表达式

7. `LAndExp` ，`LOrExp`，`EqExp`，`RelExp`： 逻辑计算的表达式

```java
    // 对表达式进行处理，找出表达式内部的问题，同时返回表达式的类型
    private ExprType analyseExpr(AstNode node) {
        return switch (node.getName()) {
            case "<Exp>", "<ConstExp>", "<Cond>" ->
                    analyseExpr(node.getChildren().get(0));

            case "<Number>" -> {
                Token token = node.getChildren().get(0).getToken();
                yield token.getType() == TokenType.INTCON
                        ? ExprType.INT
                        : ExprType.CHAR;
            }
            case "<PrimaryExp>" -> {
                AstNode first = node.getChildren().get(0);

                // '(' Exp ')'：分析中间的 Exp
                if (first.isTerminal()) {
                    yield analyseExpr(node.getChildren().get(1));
                }

                // LVal 或 Number
                yield analyseExpr(first);
            }

            case "<LVal>" -> analyseLVal(node);

            case "<MulExp>", "<AddExp>" ->
                    analyseArithmeticExpr(node);

            case "<UnaryExp>" -> analyseUnaryExpr(node);

            case "<RelExp>", "<EqExp>",
                 "<LAndExp>", "<LOrExp>" ->
                    analyseConditionExpr(node);

            default -> throw new IllegalStateException(
                    "尚未处理的表达式节点：" + node.getName()
            );
        };
    }
```

对于不同分组的表达式有不同的处理方法。其中 `<Number>` 最简单，只需要直接找其对应的 token 的类型就行了，直接返回对应的类型。

其中比较关键的是对 `<MulExp>` 和 `<AddExp>` 的处理，其他的几乎都是一样的思想，只能说是大同小异，这里具体说说这个 `analyseArithmeticExpr`：

```java
    private ExprType analyseArithmeticExpr(AstNode node) {
        List<AstNode> children = node.getChildren();

        // 没有实际运算，直接传递孩子的类型
        if (children.size() == 1) {
            return analyseExpr(children.get(0));
        }
        // 先分析两边，保证右边的错误也能被发现
        ExprType left = analyseExpr(children.get(0));
        ExprType right = analyseExpr(children.get(2));

        Token operator = children.get(1).getToken();
        // 子表达式已经出错，不再由当前运算追加类型错误
        if (left == ExprType.ERROR || right == ExprType.ERROR) {
            return ExprType.ERROR;
        }
        boolean sameType = left == right;
        boolean basicType = left == ExprType.INT
                || left == ExprType.CHAR;

        if (!sameType || !basicType) {
            report(operator, "e");
            return ExprType.ERROR;
        }
        // INT 运算得到 INT，CHAR 运算得到 CHAR
        return left;
    }
```

这里要注意这个 `ExprType.ERROR` 这个类型，这个其实很关键，举一个例子：

```C
int a = 1;
char b = 2;
int c = a + b + 3;
```

在处理 c 这个表达式的时候，a 和 b 的类型不一样，那么就会在处理 a + b这个时候输出一个错误，那之后呢，继续往后面 处理到 + 3 的时候，会不会继续输出错误呢？实际上 a + b 都是错误的了，剩下的处理其实没有什么用了，但是实验的要求是在出现错误的时候还要继续往下进行分析错误，所以这里使用一个 ERROR 类型来表示 a + b 的结果，这样就在后续处理的过程中，如果处理的部分中已经出现了 ERROR，那就不应该继续输出错误了，因为这个已经在前面输出了错误，而且说白了，这里你也无法输出错误。

这个部分的内容非常丰富，但其实总体的思路是一样的，都是根据这个语法一步一步解析其中的类型，如果出现问题通过report报告这个问题。个人感觉这个地方应该是一个非常困难的地方了，本人写的时候在这个地方思考了很久，最终在 gpt 的帮助下完成，代码也是 gpt 生成的居多。本人对这段的理解也比较浅显，这里就不过多不懂装懂了。

```java
    private void analyseStmt(AstNode node) {
        List<AstNode> children = node.getChildren();
        AstNode first = children.get(0);
        if("<LVal>".equals(children.get(0).getName())) {
            checkAssignment(node);
            return ;
        }

            TokenType type = first.getToken().getType();
            switch (type) {
                case RETURNTK -> {
                    checkReturn(node);
                    return;
                }
                case SWITCHTK -> {
                    switchDepth++;
                    try {
                        checkSwitch(node);
                    } finally {
                        switchDepth--;
                    }
                    return;
                }
                case PRINTFTK -> {
                    checkPrintf(node);
                    return;
                }
                case WHILETK -> {
                    loopDepth++;
                    try {
                        for(var child : node.getChildren()) {
                            traverse(child);
                        }
                    } finally {
                        loopDepth--;
                    }
                    return ;
                }
                case BREAKTK -> {
                    // break 必须处于 while 或 switch 中
                    if (loopDepth == 0 && switchDepth == 0) {
                        report(first.getToken(), "m");
                    }
                    return;
                }
                case CONTINUETK -> {
                    // continue 必须处于 while 中
                    if (loopDepth == 0) {
                        report(first.getToken(), "m");
                    }
                    return;
                }
            }
        }
        for (AstNode child : children) {
            traverse(child);
        }
```

```java
    private void checkAssignment(AstNode node) {
        AstNode lValNode = null;
        AstNode expNode = null;
        for (AstNode child : node.getChildren()) {
            if ("<LVal>".equals(child.getName())) {
                lValNode = child;
            } else if ("<Exp>".equals(child.getName())) {
                expNode = child;
            }
        }
        if (lValNode == null || expNode == null) {
            return;
        }

        Token lValToken = lValNode.getChildren().get(0).getToken();
        Symbol lValSymbol = findSymbol(lValToken.getLexeme());

        if(lValSymbol != null && isConstant(lValSymbol)) {
           report(lValToken, "h");

        if (left == ExprType.ERROR || right == ExprType.ERROR) {
            return;

        if (left != right) {
            Token token = lValNode.getChildren().get(0).getToken();
            report(token, "e");
        }
    }
```
